# Orbis beta 23

## App-store refresh and app updates

- Show one connection label: the configured server IP when connected, or Connecting/Reconnecting while the live stream is unavailable. Align the label and status dot across desktop and mobile layouts.

- Keep the last available app-store checkout when its Git server cannot be reached. Failed first clones stay outside the catalogue and are cleaned up.
- Report failed refreshes with the affected store names. Refresh each enabled store once per request, and allow startup to use a cached catalogue while offline.
- Keep update-review steps in a stable order while files load. Show a retry action and block updating if the review cannot be loaded or parsed.
- Keep the update wizard and backup choice available when the server rejects an update request. Navigate after the request is accepted; ongoing work remains visible in Tasks.
- Correct keyboard step navigation, wrap footer controls at narrow widths, use the shared focus colour and remove the repeated update heading.

Runtipi compatibility remains 4.10.1. The complete product acceptance checklist and the separate Hades deployment phase remain open.
