# Orbis beta47

## Local account recovery

- Enforce the normal eight-character password minimum during local operator recovery. Invalid input leaves the request and account unchanged.
- Accept only a decimal Unix-second request timestamp within the current fifteen-minute window. Reject missing, malformed, future, millisecond and expired requests with HTTP400.
- Reject overlapping recovery in the single backend process with HTTP409. Release the in-progress flag after success or failure so a legitimate retry can proceed.
- Keep the existing local CLI authorization requirement. Dashboard sessions, app-host sessions and unauthenticated requests cannot reset the operator password; there is no public reset-status or cancellation endpoint.
- Revoke operator sessions after changing the password and before clearing the request. If request cleanup fails, report that the new password is already active and server cleanup is still required. Retain the existing behavior of disabling two-factor enrollment during local recovery.
