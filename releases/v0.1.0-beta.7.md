# Orbis v0.1.0 beta 7

This remains a development preview for isolated homelab testing. It targets the Runtipi v4.10.1 data and application layout.

## Since beta 6

- Fixed a Workspace save-status race still present in beta 6. Pinning or rearranging now changes the label to “Saving layout…” in the same interaction, and a late response from an older save cannot mark a newer change as saved.
- Kept locally edited preferences if an initial server read finishes after the edit, then syncs them once the server is ready.

## Verification

- The published beta 6 arm64 image was reached through the host update transaction on a synthetic CLI installation. The beta 5 rollback snapshot verified, the core became healthy at its exact digest, and the inherited Whoami app remained installed.
- The beta 6 image reproduced the stale save label in a real Chrome session. A local arm64 image with this correction passed the same pin/unpin interaction, response-backed persistence, desktop and 390px Workspace views without horizontal overflow, and no page errors.
- Repository CI and integration tests gate this release. Runtime validation of this tag's published image is a separate step after publication.

## Current limits

The host update command works only after Orbis has already been enrolled on a CLI v4.10.1 installation. It requires managed apps to be stopped and does not capture data on external mounts or Docker volumes outside the installation tree. There is no first stock-to-Orbis installer, browser release apply, host package updater, or multi-server pairing yet. No real homelab data has been migrated. Do not replace a production Runtipi installation with this preview.
