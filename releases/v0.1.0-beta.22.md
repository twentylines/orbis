# Orbis v0.1.0 beta 22

## Desktop windows

- Float, move and resize first-party tools; maximize or snap into the available workspace. Placement is saved separately for each tool and clamped after display changes.
- Minimize contracts the current tool toward the dock and opens Home. Restore keeps the exact route, tab/range and unsaved form. Closing or choosing another tool follows normal navigation and replaces the current route instance.
- Keyboard alternatives provide move/resize, fine steps, save and cancel. Phones and short viewports use full-page tools. Reduced motion and missing browser animation APIs use immediate visibility changes.
- Keep the system bar and dock accessible, with consistent title-bar controls, visible focus and truncated long server labels.

## Efficient background behavior

- Close minimized app/system log streams and pending retries. Pause hidden metric history and tool polling; keep global app events and task status live.
- Preserve editor loader data during visibility-only navigation. An unrelated custom-app uninstall no longer discards a different tool's draft.
- Save placement after gestures, with no preference writes during pointer movement and one debounced write on commit.

## Layout and correctness

- Adapt Store, Apps, Monitor, Docker resources, Updates and Appearance to the window's width. Keep long Store headings clear of their descriptions and retain internal scrolling.
- Correct create/edit/update titles and input-label associations. Use stable system-log row IDs and the API's 1–1000-line limit.
- Honor ignored app versions in Home attention counts. Persist only declared appearance/workspace fields and validated window geometry.
