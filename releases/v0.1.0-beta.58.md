# Orbis beta58

## App backups

- Check copies, archive creation and extraction before reporting success. Keep incomplete archives out of the backup list.
- Preserve file ownership, permissions and timestamps, including hidden files and directories.
- Stage restored data before replacing the current files. Retain recovery information until the restored version is recorded and cleanup finishes.
- Recover an interrupted restore before app startup or another app operation. The app stays stopped after recovery so its state can be reviewed.
- Include the MIME detection and archive tools required by the runtime image.

## Backup screens

- Wrap long filenames and reflow dates, sizes and actions on smaller screens.
- Keep restore and delete actions visible while long backup details scroll.

Backups cover Orbis-managed app directories and configuration overrides. External data needs a separate backup. Restore is refused when a managed app directory is itself a mount point or contains nested mounts. See [App backups](https://github.com/twentylines/orbis/blob/main/BACKUPS.md) for recovery and storage requirements.

This is a prerelease. Linux filesystem recovery checks and API integration tests use disposable data; they do not establish migration safety for an existing homelab.
