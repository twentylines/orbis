# Orbis v0.1.0 beta 4

This remains a development preview for isolated homelab testing. It targets the Runtipi v4.10.1 data and application layout.

## Since beta 3

- Workspace uses the same authenticated live telemetry as Monitor. Its CPU and memory readings are labelled as host readings, while network activity is labelled as Orbis core-container activity.
- A host command can enroll an already healthy, digest-pinned Orbis CLI installation and start or stop that same release while always including the Orbis Compose override. It records hashes of the local configuration and requires an explicit Docker context and installation root for mutations.
- Deployment documentation now identifies the stock Runtipi CLI start and update paths that would replace an Orbis core, and describes the verified operating boundary for the new host command.

## Verification

- Beta 3's published arm64 image booted healthy on a stopped, synthetic Runtipi CLI v4.10.1 copy. Its attached manifest and the GHCR OCI index returned the same digest; the index includes amd64 and arm64.
- The isolated host command enrolled that published image, stopped the core, started it again, and reported the exact image digest and healthy state. Fifteen Python safety tests passed.
- Desktop and mobile browser fixture checks passed for the shared Workspace telemetry in the source tree. Repository CI and integration tests gate this release.

## Current limits

The host command is for an Orbis installation that has already been manually migrated and verified. It does not perform the first cutover, release update, snapshot, or rollback. No real homelab data has been migrated. Host package updates and multi-server pairing are not included. Do not replace a production Runtipi installation with this preview.
