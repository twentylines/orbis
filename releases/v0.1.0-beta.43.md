# Orbis beta 43

## Host processes in Monitor

- Show the top 20 host processes by CPU or resident memory, highest first. Keep process names and PIDs readable, with full accessible names when an unusually long identifier needs ellipsis.
- Include processes inside containers without adding their readings into a misleading total. CPU uses two recent samples of the same process; new or reused PIDs, counter resets and long gaps wait for another comparison. Memory is available immediately.
- Show stale samples, unreadable processes and limited scans explicitly. Process readings remain available independently of Orbis core telemetry.
- Share one bounded on-demand collector across viewers. Scan at most 8,192 processes and one second of work, limit each stat read to 4 KiB, and retain only bounded counters and top-20 rankings. The process collector runs separately from filesystem probes.

Install or upgrade the restricted host service from a reviewed checkout to include `orbis-host-processes.py`. Updating the core image does not replace that service. Older helpers retain their existing operations and report the missing process capability. There are no process-control commands. See [HOST-SERVICE.md](https://github.com/twentylines/orbis/blob/main/HOST-SERVICE.md).

## Layout, themes and reading position

- Match Monitor card gutters to the actual content width, including smaller desktop windows. Keep title typography consistent and enlarged words inside comfortable padding.
- Preserve the natural reading position when ranked PIDs move during a refresh. Keep focus visible when the list grows and restore Retry focus without taking it from another selected control.
- Retain the shared translucent palette blur for the system bar, coloured titlebars and dock, with no white frame rims.
