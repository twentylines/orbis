# Orbis v0.1.0 beta 13

This remains a development preview based on Runtipi v4.10.1. Hades has not been changed.

## Since beta 12

- Added a guarded in-place upgrade command for the separate Linux host helper. It reviews the installed and candidate script and unit hashes, checks the enrolled core and socket mount, and refuses a running or interrupted core update.
- The helper upgrade stages root-owned files, stops the old service under the host-operation lock, then verifies the replacement from both the host and Orbis core. A failed replacement restores the previous helper; an interrupted upgrade has a recovery command.
- The newer helper rejects new core update operations while its maintenance record exists. Reapplying identical helper files leaves the running service alone.

## Verification before publication

- The isolated Linux VM upgraded its installed beta 11 helper while the Orbis core remained healthy at beta 12. Installed and candidate script hashes matched after the upgrade.
- A deliberately failing replacement service restored the previous helper, its socket, and the healthy Orbis core. Simulated interrupted and verified-cleanup states passed recovery. A new plan was rejected during maintenance with HTTP 409.
- All 53 Python tests passed locally. GitHub CI and integration tests gate publication.

## Current limits

The helper upgrade remains validated only on synthetic arm64 data. Real homelab data, external mounts and named volumes, amd64 runtime, host OS package updates, and multi-server pairing remain unverified or unimplemented. This release is for isolated testing, not a live Runtipi replacement.
